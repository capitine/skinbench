# Security Policy

## Supported version

Security fixes are supported for the latest public beta only. Older betas may
be asked to update before a report is investigated.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/capitine/skinbench/security/advisories/new)
for a suspected vulnerability. Do not open a public issue for a security
report or publish exploit details before a fix is available.

Use [GitHub Issues](https://github.com/capitine/skinbench/issues) for ordinary
bugs that do not expose data, execute unintended code, bypass a safety guard,
or create another security risk.

## Protect project data

Do not attach or upload any of the following:

- proprietary rigs or scenes;
- client data;
- credentials or tokens;
- logs containing private paths;
- skin-weight snapshots.

Create the smallest disposable reproduction that demonstrates the problem.
Replace project names, node names, and local paths with neutral examples.

## What to include

Describe the affected SkinBench version, Maya version, operating system,
expected result, observed result, and the smallest safe steps that reproduce
the issue. State whether the report involves installation, local file access,
scene changes, a weight write, or a folder-opening control.

Reports are handled on a best-effort basis. No response time is promised.
